# API reference audiences

The OpenAPI operation extension `x-audiences` drives the storefront and back-office references. Storefront covers operations suitable for a guest or customer API token in its own shopper context. Back-office covers staff operations and trusted integrations, including operations whose ordinary responses carry operational fields. A shared operation supports both workflows, subject to its caller and resource checks.

Audience metadata describes recommended usage. The bearer policy, nopCommerce permissions, ownership checks and store scope still govern requests. `POST /token` allows anonymous access. The other operations require a bearer token and the API Users role. Treat cart, product, customer and order detail responses as server-side data when building a storefront. The checkout guide describes the full server-side flow.

| Operations | Audience | Permission and scope |
| --- | --- | --- |
| `POST /token` | Both | The anonymous token action issues a token for a new guest or validates account credentials. The guest path assigns the API role. An account must already hold the API role to call protected endpoints. |
| `GET /token/check` | Both | Checks the bearer policy, resolves the token’s customer record and returns an empty success response. |
| `GET /api/checkout/shipping-options` | Both | An owner with cart permission can quote against their current-store cart and an address in their own address book. Passing another customer ID requires an administrator with order write permission. The response returns option names, provider identifiers and rates. |
| `GET /api/checkout/payment-methods` | Both | Uses the same cart permission and administrative delegation as shipping quotes. Resolves available payment plugins for the customer, store and billing country. Both discovery actions enforce checkout settings and guest eligibility. |
| `GET /api/checkout_attributes` | Storefront | Requires cart permission. Resolves controls and the caller’s stored selections in the current store, applying attribute mappings and shipping requirements. |
| `GET /api/countries` | Both | The country service lists published countries mapped to the current store. Billing and shipping eligibility filters support address entry and integration validation. |
| `GET /api/countries/{id}` | Both | Looks up a country by ID, including historical references. Returns directory data without customer records or administrative writes. |
| `GET /api/stateprovinces` | Both | Returns the state/province directory from the service’s default published query. |
| `GET /api/stateprovinces/{id}` | Both | Looks up a state/province by ID for address display or reconciliation, without changing directory data. |
| `GET /api/currencies`, `GET /api/languages` | Both | Uses the published service lists. The optional store ID narrows the lookup, and omission returns published entries across stores. Supports localization and integration lookups. |
| `GET /api/currencies/primary` | Both | Resolves the configured primary store currency for commerce and integration currency handling. |
| `GET /api/currencies/current`, `POST /api/currencies/current`, `GET /api/languages/current`, `POST /api/languages/current` | Storefront | Reads or sets the authenticated customer’s own preferences. Setters resolve the submitted ID directly and return no data about other customers. |
| `GET /api/stores/current` | Back-office | The action overrides the controller’s store-management permission and resolves the current store. The default DTO includes configured host aliases and company details, so use it within a trusted integration. |
| `GET /api/stores` | Back-office | Requires store-management permission and lists all configured stores. |
| `GET /api/customers/me` | Back-office | Overrides the controller’s customer-write permission and looks up the token owner. The default customer projection includes administrative comments and role IDs, so use it within a trusted integration. |
| `GET /api/customers`, `GET /api/customers/{id}`, `GET /api/customers/count`, `GET /api/customers/search`, `POST /api/customers`, `PUT /api/customers/{id}`, `DELETE /api/customers/{id}` | Back-office | Requires customer write permission at controller scope. Lists, counts and text search use the current store. ID-based actions work with customer records by ID. Role changes and administrator accounts have additional checks. |
| `POST /api/customers/{customerId}/billingaddress`, `POST /api/customers/{customerId}/shippingaddress` | Both | Overrides the controller-level permission and allows the token owner to set their own address. Another customer requires customer write permission. Finds or inserts an address in the target customer’s address book and returns the address DTO. |
| `GET /api/customer_roles` | Back-office | Requires customer write permission. Lists configured role records. |
| `GET /api/categories`, `GET /api/categories/count` | Back-office | Requires public-store navigation permission. The query applies current-store mapping, leaves publication optional, and does not apply customer ACL filtering. Unpaged category lists require an administrator. |
| `GET /api/categories/{id}` | Back-office | Requires public-store navigation permission. Fetches any non-deleted category by ID without checking publication, store mapping or ACL. |
| `POST /api/categories`, `PUT /api/categories/{id}`, `DELETE /api/categories/{id}` | Back-office | Requires category write permission for catalog management. |
| `GET /api/products`, `GET /api/products/count` | Back-office | Requires public-store navigation permission. The current-store query leaves publication optional and does not apply customer ACL filtering. List DTOs include product cost and stock data. Unpaged product lists require an administrator. |
| `GET /api/products/{id}` | Back-office | Requires public-store navigation permission. Applies current-store mapping, caller ACL and vendor scope to non-deleted products. The lookup does not require publication, and the DTO includes product cost and stock data. |
| `GET /api/products/categories` | Back-office | Requires public-store navigation permission. Reads mapping IDs for submitted product IDs and resolves categories without shopper publication, store or ACL checks. |
| `POST /api/products`, `PUT /api/products/{id}`, `DELETE /api/products/{id}` | Back-office | Requires product write permission for catalog management. Update also checks the product against the caller’s vendor, store and ACL scope. |
| `POST /api/products/bulk-price-stock`, `POST /api/products/desired-price-stock`, `GET /api/sync/capabilities` | Back-office | Requires product write permission. Stock and price synchronization applies store, actor ACL and vendor constraints to the target product. Capability lookup supplies synchronization feature availability. |
| `GET /api/products/{productId}/pictures/sync/{key}`, `PUT /api/products/{productId}/pictures/sync/{key}`, `GET /api/products/{productId}/pictures/{mappingId}/{pictureId}/sync`, `PUT /api/products/{productId}/pictures/{mappingId}/{pictureId}/sync` | Back-office | Requires product write permission. Reads and updates product picture reconciliation state, with product ownership/scope checks and linked mapping validation. |
| `GET /api/manufacturers`, `GET /api/manufacturers/count`, `GET /api/manufacturers/{id}`, `POST /api/manufacturers`, `PUT /api/manufacturers/{id}`, `DELETE /api/manufacturers/{id}` | Back-office | Requires manufacturer write permission at controller scope, including reads. Supports catalog synchronization and maintenance. |
| `GET /api/productattributes`, `GET /api/productattributes/count`, `GET /api/productattributes/{id}`, `POST /api/productattributes`, `PUT /api/productattributes/{id}`, `DELETE /api/productattributes/{id}` | Back-office | Requires both product and product-attribute write permissions at controller scope. Reads and writes attribute definitions. |
| `GET /api/specificationattributes`, `GET /api/specificationattributes/count`, `GET /api/specificationattributes/{id}`, `POST /api/specificationattributes`, `PUT /api/specificationattributes/{id}`, `DELETE /api/specificationattributes/{id}` | Back-office | Requires specification-attribute write permission at controller scope. Manages attribute definitions and options. |
| `GET /api/productspecificationattributes`, `GET /api/productspecificationattributes/count`, `GET /api/productspecificationattributes/{id}`, `POST /api/productspecificationattributes`, `PUT /api/productspecificationattributes/{id}`, `DELETE /api/productspecificationattributes/{id}` | Back-office | Requires both product and specification-attribute write permissions. Manages specification values assigned to products. |
| `GET /api/product_category_mappings`, `GET /api/product_category_mappings/count`, `GET /api/product_category_mappings/{id}`, `POST /api/product_category_mappings`, `PUT /api/product_category_mappings/{id}`, `DELETE /api/product_category_mappings/{id}` | Back-office | Requires both product and category write permissions. Manages product-to-category associations. |
| `GET /api/product_manufacturer_mappings`, `GET /api/product_manufacturer_mappings/count`, `GET /api/product_manufacturer_mappings/{id}`, `POST /api/product_manufacturer_mappings`, `PUT /api/product_manufacturer_mappings/{id}`, `DELETE /api/product_manufacturer_mappings/{id}` | Back-office | Requires both product and manufacturer write permissions. Manages product-to-manufacturer associations. |
| `GET /api/product_warehouse_inventories`, `GET /api/product_warehouse_inventories/{id}`, `POST /api/product_warehouse_inventories`, `PUT /api/product_warehouse_inventories/{id}`, `DELETE /api/product_warehouse_inventories/{id}` | Back-office | Requires product write permission. Reads and writes inventory by warehouse. Readback applies current-store mapping, caller ACL and vendor scope to the associated product. |
| `GET /api/warehouses`, `GET /api/warehouses/{id}`, `POST /api/warehouses`, `PUT /api/warehouses/{id}`, `DELETE /api/warehouses/{id}` | Back-office | Requires shipping-settings management permission. Manages warehouse configuration and its addresses. |
| `GET /api/menus`, `GET /api/menus/{menuId}/items`, `POST /api/menus/{menuId}/items`, `PUT /api/menus/{menuId}/items/{itemId}`, `DELETE /api/menus/{menuId}/items/{itemId}` | Back-office | Requires menu write permission, including reads. Manages the store’s menu records and their item ordering. |
| `GET /api/topics`, `GET /api/topics/{id}`, `POST /api/topics`, `PUT /api/topics/{id}`, `DELETE /api/topics/{id}` | Back-office | Requires topic write permission at controller scope, including reads. Manages content records and publication. The list queries the current store, and ID-based actions resolve individual topic records. |
| `GET /api/news_letter_subscriptions`, `POST /api/news_letter_subscriptions/{email}/deactivate` | Back-office | Requires subscriber write permission. Lists subscriber records or deactivates subscriptions that match the email in the current store. |
| `GET /api/taxcategories`, `GET /api/taxcategories/{id}`, `POST /api/taxcategories`, `PUT /api/taxcategories/{id}`, `DELETE /api/taxcategories/{id}` | Back-office | Requires tax-settings management permission. Manages tax category configuration. |
| `POST /api/admin/cache/clear` | Back-office | Requires maintenance permission. Clears the application cache and records the caller in the activity log. |
| `GET /api/shopping_cart_items` | Back-office | Own-cart or wishlist requests require the corresponding public-store permissions and an explicit matching customer ID. Cross-customer or unscoped lists require order write permission. Cart items include a full product DTO. |
| `GET /api/shopping_cart_items/me` | Back-office | Reads the token owner’s current-store cart with cart permission. The nested product DTO includes product cost and inventory data. |
| `POST /api/shopping_cart_items`, `POST /api/shopping_cart_items/batch`, `PUT /api/shopping_cart_items/{id}` | Back-office | Requires cart or wishlist permission for the caller’s own items and order write permission for another customer’s items. The default response includes the full product DTO. |
| `DELETE /api/shopping_cart_items`, `DELETE /api/shopping_cart_items/{id}` | Both | An owner with cart or wishlist permission can remove their own items. Bulk deletion defaults to the token owner and validates requested item IDs. Order write permission can authorize another customer’s cart. Responses include no product data. |
| `GET /api/orders`, `GET /api/orders/{id}`, `GET /api/orders/customer/{customerId}` | Back-office | Uses current-store scope. Own orders require cart permission. Other customers’ orders and unscoped lists require order-view permission. Default order DTOs include item cost and full nested product records. |
| `GET /api/orders/count` | Both | Uses current-store scope and the same owner/order-view split. Returns a count for the submitted customer, or a store-wide count for callers with order-view permission when no customer is supplied. |
| `GET /api/orders/{orderId}/pdf-invoice` | Both | Uses current-store order scope and the same owner/order-view split. Returns the generated customer invoice as a PDF payload. |
| `POST /api/orders` | Back-office | An owner with cart permission may place an order, and order write permission authorizes acting for another customer. Validates address ownership, the current store and the cart. Successful responses ordinarily include full order and item DTOs with cost data. |
| `PUT /api/orders/{id}`, `DELETE /api/orders/{id}` | Back-office | Require order write permission and current-store order scope. These operations edit or delete existing orders. |
| `GET /api/orders/{orderId}/items`, `GET /api/orders/{orderId}/items/{orderItemId}` | Back-office | Resolves the parent order in the current store. An owner needs cart permission, and access to another customer’s order needs order-view permission. The item DTO includes original product cost and the full product DTO. |
| `GET /api/orders/{orderId}/items/count` | Both | Uses the same current-store, owner and order-view checks as the order item reads. Returns a count without item details. |
| `POST /api/orders/{orderId}/items`, `PUT /api/orders/{orderId}/items/{orderItemId}`, `DELETE /api/orders/{orderId}/items/{orderItemId}`, `DELETE /api/orders/{orderId}/items` | Back-office | Require order write permission and a parent order in the current store. Individual item lookups use the parent order ID. |
| `GET /api/orders/{orderId}/shipments`, `GET /api/orders/{orderId}/shipments/{shipmentId}` | Back-office | Require shipment-view permission, a non-vendor caller and an order in the current store. Shipment details include administrative comments. |
| `POST /api/orders/{orderId}/shipments`, `PUT /api/orders/{orderId}/shipments/{shipmentId}`, `POST /api/orders/{orderId}/shipments/{shipmentId}/ship`, `POST /api/orders/{orderId}/shipments/{shipmentId}/ready-for-pickup`, `POST /api/orders/{orderId}/shipments/{shipmentId}/deliver` | Back-office | Require shipment write permission, a non-vendor caller and an order in the current store. Mutation and transition logic checks shipment/order relationships and validates the fulfillment state. |
